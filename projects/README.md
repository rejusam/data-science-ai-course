## What every project needs

Each project ends in its own public GitHub repository, not a folder in this
one. That repository is the deliverable, and it is what you show employers.

It needs:

- A README explaining the question you asked, the data you used, what you did,
  and what you found. Write it for someone who has never seen the project.
- Notebooks that run top to bottom on a fresh clone without errors.
- An honest statement of limitations. Saying what your model cannot do reads
  as competence, not weakness.

## Choosing a topic

Pick something you actually care about. You will spend weeks with it, and the
difference in finished quality between a topic you chose and one you settled
for is obvious to everyone including you.

Write the question down before you touch the data.
